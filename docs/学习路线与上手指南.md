# Shell_UE 插件学习路线与上手指南

> 面向对象：要在**自己的项目**里使用 Shell_UE（游戏内伪终端）的开发者。
> 前置：UE 5.8 工程基础、C++ 基础。预计总时长 2~3 天（不含 GAS 深化）。
>
> 本路线所有文件路径基于 `UE_Shell_Project` 壳工程；`docs/` 为中文名文档（2026-09-01 已重命名）。

## 阶段 0 · 跑起来（先玩，再学）

### 0.1 启动

1. 用 UE 5.8 打开 `D:\SSDWP\UE\UE_Shell_Project\UE_Shell_Project.uproject`（首次会编译）。
2. PIE 运行 `MainMenu` 关卡（或直接打开 `Plugins/Shell_UE/Content/Shell/Maps/MainMenu.umap`）。

### 0.2 终端实操路线（按此顺序输入，约 15 分钟）

| 步骤 | 输入 | 看什么 |
| --- | --- | --- |
| 1 | `Tab` | 唤出/关闭终端（IA_TerminalToggle，可在 `IMC_Shell` 里重绑定） |
| 2 | `help` | 全部命令清单（按分类分组） |
| 3 | `ls` / `pwd` / `cd games` / `cd ..` | 虚拟文件系统（`UShellVirtualFS`，全内存，不碰磁盘） |
| 4 | `cat readme.txt` | 读文件（配合 `echo hello > f.txt` 先造一个） |
| 5 | `echo 你好` / `date` / `time` | 输出与时间命令 |
| 6 | `history` / `↑` `↓` | 命令历史 |
| 7 | `spawncube` | 在游戏世界生成一个立方体（命令和玩法互动的第一个例子） |
| 8 | `cast fireball` | 施放火球（GAS 联动，看 `on cooldown` 与蓝耗反馈） |
| 9 | `attributes` / `cooldowns` | 读属性集 / 冷却状态 |
| 10 | `login alice` | 登录流程（密码 `alice123`；`username:` / `password:` 提示流）→ 自动进入 `Gameplay` 关卡 |
| 11 | `open` / `tp` / `setvar` | 登录后才有权用的开发命令（`help` 里默认隐藏） |
| 12 | `qcmd` / `store` / `sh` | 快捷指令 / 指令商店 / 脚本执行（高级功能，先混个脸熟） |

> 验收截图参考：`Plugins/Shell_UE/RawContent/qa/p2-01-menu-login-prompt.png` ~ `p3-08-full-gas-flow.png`。

### 0.3 边玩边观察的 3 个点

- **输入行在滚动区里**：往上滚历史输出，输入行也跟着走——这是行池化的结果（不是 Bug）。
- **光标是原生竖线**：`SEditableText` 自带 caret（曾自制方块光标，2026-09-01 已移除，理由见 `docs/终端UI实现调研.md` 3.4）。
- **CRT 效果**：绿色荧光、扫描线、暗角、闪烁——全部由 Slate 叠层 + 两个材质 + 一个 4×4 程序化贴图完成。

## 阶段 2 · 命令系统实战（写自己的第一条命令）

**核心认识**：命令 = 注册表里的一条 `FShellCommand`（名字 + 分类 + 帮助 + 处理函数）。加一条命令 = 写一个 `FShellCommandResult XXX(const FShellCommandContext&)` + 注册。

### 2.1 方式一：C++ 直接注册（推荐先学）

`docs/宿主接入指南.md` 第 4 章有完整代码，骨架如下（在**你的游戏模块**里做）：

```cpp
// MyGameCommands.cpp（放你的模块 Private/ 下）
#include "Shell/Terminal/ShellCommandRegistry.h"
#include "Shell/Terminal/ShellSubsystem.h"
#include "Shell/Terminal/ShellTypes.h"

namespace
{
	FShellCommandResult HandleHello(const FShellCommandContext& Ctx)
	{
		FShellCommandResult Result;
		Result.Lines.Add(FString::Printf(TEXT("Hello, %s!"),
			Ctx.Args.Num() > 0 ? *Ctx.Args[0] : TEXT("world")));
		return Result;
	}
}

// 在模块 StartupModule / GameInstance 初始化时调用一次：
void RegisterMyCommands(UShellSubsystem* Shell)
{
	FShellCommand Cmd;
	Cmd.Name = TEXT("hello");
	Cmd.Category = TEXT("Mine");
	Cmd.Help = TEXT("hello [name]  Say hello");
	Cmd.Handler = HandleHello;   // FShellCommandHandler
	Shell->GetRegistry().RegisterCommand(Cmd);
}
```

> 注意：`UShellSubsystem` 是 **GameInstance 子系统**，注册时机选在 `Initialize()` 或 `StartupModule` 之后、玩家输入前即可。

### 2.2 方式二：DataTable 数据驱动（零编译）

- 行结构：`FShellCommandRow`（`ShellDataTableRows.h:66`）——可标记 **Cpp**（转发到内置 C++ 命令）、**Alias**（转发到另一条命令）、**Blueprint**（路由到蓝图库）。
- 资产：`/Shell_UE/Shell/Data/DT_ShellCommands`，在 `UShellSettings` 里指定表。
- 适用：策划配表改命令，不动代码。

### 2.3 练习清单（做完即出师）

1. 注册一条 `hello` 命令（带参数默认值）。
2. 让它支持 `hello | cat`（管道）——看 `FShellCommandContext::StdinLines`。
3. 用 DataTable 把 `hello` 改名为 `hi`（Alias），零编译生效。
4. 让命令输出走 `EShellOutputType::Error`，观察红色输出与 `GetColorForType`。

踩坑参考：`RawContent/doc/开发踩坑记录/04-命令系统与数据驱动.md`。

## 阶段 3 · 接入你自己的项目（照做即可）

完整十章节指南在 **`docs/宿主接入指南.md`**，这里给最小清单：

### 3.1 安装（三种方式任选）

```bash
# 方式 A：git 子模块（推荐，可随时更新）
git submodule add git@github.com:youli42/Shell_UE.git <你的工程>/Plugins/Shell_UE
# 方式 B：直接复制 Plugins/Shell_UE 目录过去
# 方式 C：只拷贝 Content/Shell + 源码，自管依赖（不推荐，维护成本高）
```

### 3.2 启用与依赖

```jsonc
// .uproject 的 Plugins 段加：
{ "Name": "Shell_UE", "Enabled": true }
```

```csharp
// 你的游戏模块 Build.cs：
PublicDependencyModuleNames.AddRange(new string[] { "UMG", "EnhancedInput", "GameplayAbilities", "GameplayTags", "GameplayTasks" });
PrivateDependencyModuleNames.AddRange(new string[] { "Slate", "SlateCore" });
```

### 3.3 接线（复制壳工程写法）

`Source/UE_Shell_Project/ShellProjectPlayerController.cpp` 两个函数：
- `BeginPlay`：`AddMappingContext(IMC_Shell, 0)`（资产路径 `/Shell_UE/Shell/Input/IMC_Shell`）
- `SetupInputComponent`：`BindAction(IA_TerminalToggle, Started, HandleTerminalToggle)` → `Shell->ToggleTerminal(this)`

### 3.4 打包必要条件（**不做会炸**，UE 5.8 特性）

宿主的 `Config/DefaultGame.ini` 必须加（插件 Config 不并入配置链）：

```ini
[/Script/UnrealEd.ProjectPackagingSettings]
+MapsToCook=(FilePath="/Shell_UE/Shell/Maps/Gameplay.umap")
+DirectoriesToAlwaysCook=(Path="/Shell_UE/Shell/Fonts")
+DirectoriesToAlwaysCook=(Path="/Shell_UE/Shell/Data")
+DirectoriesToAlwaysCook=(Path="/Shell_UE/Shell/Input")
+DirectoriesToAlwaysCook=(Path="/Shell_UE/Shell/Libraries")
```

### 3.5 验证清单

- [ ] Tab 能唤出终端，`help` 有输出
- [ ] `login alice` 能走通登录并切关卡（或不想要登录流，直接在 GameMode 里关掉）
- [ ] 打包后终端字体不是方块（F_CJK 已 Inline，确认 Fonts 目录被 cook）
- [ ] `spawncube` 在你的关卡里能生成物体

## 阶段 4 · GAS 联动与定制（可选深化）

评估结论见 **`docs/GAS接入可行性评估.md`**，要点：

1. **自带示例**：`cast fireball` / `attributes` / `cooldowns` 已经接好（ASC 挂在 PlayerState，与 Lyra 同范式）。
2. **换自己的能力**：
   - 继承 `UShellProjectAbility` 写自己的 GA + 自己的 CostGE/CooldownGE（参考 `ShellProjectAbility.h:26/:36`）；
   - 在 `DT_ShellAbilities` 加一行（DisplayName / AbilityTag / CooldownTag / ManaCost）；
   - 在 `DefaultGameplayTags.ini` 补 Tag；`cast <DisplayName>` 即可触发。
3. **深化路线**（A~E 阶段）：数据驱动授予 → 伤害执行 → 死亡重生 → Cue+按键绑定 → ASC 子类化。
